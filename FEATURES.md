# Features

## Reaches Dock

The **Reaches** dock detects and curates reach epochs from SLEAP pose data. It
is designed for fixed-camera pellet reaching workflows and supports both 2D
single-camera inputs and 3D triangulated inputs.

The dock converts selected skeleton nodes into per-frame trajectories, runs one
of two KPN-style reach detectors, displays the detected epochs in a table, and
mirrors them as horizontal bars in the zoomed timeline.

## Core Concepts

A reach is stored as:

- `Start`: the first frame of the reach epoch.
- `Max`: the frame of maximum outward extension.
- `End`: the final frame of the reach epoch.
- `Duration`: `End - Start`, in frames.
- `Outcome`: one of `Unclassified`, `Grabbed`, `Missed`, `Dropped`, or
  `Stalled`.

Internally, saved reach segments use zero-based frame indices and the canonical
ReachX-compatible columns:

```text
frame  max_delta  dur  result  hand_pos
```

where `max_delta = Max - Start` and `dur = End - Start`.

## Hand Node Assumptions

Reach detection does not use every skeleton node. It uses selected nodes for:

- **Left hand (LH)**
- **Right hand (RH)**
- **Pellet**

The LH and RH node lists are shown in the **Hand Nodes** section. The detector
requires at least one checked LH node and one checked RH node.

### Auto-Selected Hand Nodes

The dock first looks for the preferred reach-hand node names:

```text
wrist_mid_L, wrist_pinky_L, mid_pinky_L, tip_pinky_L, tip_index_L,
mid_index_L, wrist_index_L, tip_ring_L, tip_middle_L

wrist_mid_R, wrist_pinky_R, mid_pinky_R, tip_pinky_R, tip_index_R,
mid_index_R, wrist_index_R, tip_ring_R, tip_middle_R
```

If those are not present, it falls back to keyword matching. Hand-like names
include words such as `hand`, `paw`, `wrist`, `finger`, `thumb`, `palm`, and
`forelimb`. Side is inferred from left/right tokens such as `left`, `right`,
`lh`, `rh`, `_L`, and `_R`.

### Pellet Node

Pellet detection is stricter: the pellet node must be named exactly `pellet`,
case-insensitively. The **From pellet** method requires this node. The
**Absolute** method can run without a pellet node, but outcome classification is
limited without pellet context.

### Multiple Selected Nodes

If multiple nodes are selected for a hand, the dock averages them into one
per-frame hand trajectory.

For 2D label/prediction sources, the average is confidence-weighted when point
scores are available. For points3D sources, selected 3D nodes are averaged with
`nanmean`.

## Prediction Sources

The **Predictions Source** section controls where trajectories come from.

### Project Labels

If no external source is loaded, the dock uses the currently open project
labels and current video.

For each frame, it considers both predicted instances and user instances. This
means manual corrections in the project can contribute to the trajectories.

Coordinates are the video/image coordinates from SLEAP labels:

- 2D `x, y` are in **pixels**.
- `z` is filled with `0.0` when a 3D-shaped trajectory is needed.
- Distance-based computations therefore operate in **pixels**.

### External Prediction Files

The dock can load:

- `.slp`
- SLEAP analysis `.h5` / `.hdf5` files that contain `track_occupancy`
- `.nwb`

After loading, choose the camera/video from the **Camera** dropdown. The dock
tries to auto-select the video whose filename stem best matches the current GUI
video.

External prediction files are still 2D unless they are a separate points3D
source. Computations operate in **pixels**.

The **Discover** button searches for prediction files in a `predictions/`
subfolder next to the current video directory, and also in a `predictions/`
subfolder one directory above it. If multiple files are found, the dock prefers
a file whose stem contains the current video stem.

### points3D HDF5 Files

The optional **points3D** source loads an HDF5 file containing one of:

- `points3D`
- `points3d`
- `tracks`

The dock also reads `node_names` when present. If the file was generated by the
SLEAP 3D projection export workflow, its metadata records:

```text
coordinate_system: calibration
units: mm
```

For these files, reach computations operate in **3D calibration coordinates**,
normally **millimeters**. If you load a different HDF5 file, the detector uses
the numeric units in that file; thresholds and distance parameters must be
interpreted in those same units.

If a sibling `reprojections.h5` is available, it is used for:

- drawing LH/RH/pellet markers back onto the current camera view;
- extracting point-score confidence across reprojection cameras.

The core reach detection still uses the `points3D` coordinates, not the
2D reprojection coordinates.

## 2D vs 3D Behavior

### 2D Inputs

2D sources include project labels and external `.slp`, `.h5`, and `.nwb`
prediction files.

For these inputs:

- trajectories are extracted from image coordinates;
- `x` and `y` are pixels;
- `z` is set to `0.0`;
- Euclidean distances are pixel distances;
- thresholds such as outward threshold, minimum outward travel, and pellet-home
  distance are in pixels;
- the **Absolute Z** axis is not useful because `z` is synthetic and constant.

### 3D Inputs

3D sources are loaded through the **points3D** row.

For these inputs:

- trajectories are extracted from 3D coordinates;
- if generated by SLEAP 3D projection export, units are millimeters;
- distances are 3D Euclidean distances;
- threshold and distance parameters should be set in millimeters;
- video markers are shown from camera reprojections when available.

The dock validates 2D inputs using finite `x, y` values. It validates 3D inputs
using finite `x, y, z` values.

## Confidence Handling

The **Min point confidence** parameter filters LH, RH, and pellet trajectories.

For 2D SLEAP labels:

- selected node coordinates are weighted by their point scores;
- nodes below the confidence threshold are excluded from the weighted average;
- the per-frame trajectory confidence is the median point score over finite
  selected nodes;
- if point scores are missing, points are treated as confidence `1.0`.

For points3D inputs:

- coordinates come from `points3D`;
- if `reprojections.h5` includes `point_scores`, confidence is the median score
  across selected nodes and cameras;
- if point scores are unavailable, valid finite coordinates are treated as
  present.

Low-confidence frames are masked from distance traces before detection.

## Filter Parameters

The **Filter Parameters** section can smooth LH/RH hand trajectories before
reach detection. This is useful when frame-to-frame pose jitter makes the
estimated reach start, maximum extension, or end frame unstable.

When **Filter LH/RH traces** is enabled, the dock applies a first-order
Butterworth low-pass filter to each finite coordinate axis of the LH and RH
trajectories. The filtered LH/RH trajectories are then used by both reach
detection methods.

The filter mirrors the MATLAB-style setup:

```matlab
[b,a] = butter(1, cutoff_frequency / sampling_rate);
```

For example, with a cutoff of `30 Hz` and sampling rate of `150 Hz`, the
normalized cutoff is `30 / 150 = 0.2`.

The user controls:

- **Filter LH/RH traces**: enables or disables filtering.
- **Cutoff frequency**: low-pass cutoff in Hz. The default is `30 Hz`.
- **Sampling rate**: calculated automatically from the selected source video's
  frame rate when detection is run.

Only LH/RH trajectories are filtered. The pellet trajectory is left unchanged,
so pellet placement/loss logic still uses the original pellet measurements.

Filtering preserves the original missing-data mask: finite samples are
interpolated only to run the filter, and frames that were originally `NaN`
remain `NaN` in the filtered output. If there are too few finite samples for an
axis, that axis is left unfiltered.

For 2D inputs, the filter smooths pixel coordinates. For points3D inputs, it
smooths 3D coordinates, normally in millimeters.

## Detection Methods

The dock has two reach detection methods.

### From pellet

This is the default method. It is the fixed-camera KPN outward-peaks detector.
It requires LH nodes, RH nodes, and a `pellet` node.

The method:

1. Estimates the pellet home position from high-confidence pellet frames.
2. Computes pellet, RH, and LH distances from pellet home.
3. Finds pellet placement/loss epochs.
4. Uses the RH distance-to-pellet-home trace as the reach signal.
5. Detects upward threshold crossings in the outward signal.
6. Finds the reach start from pre-crossing velocity/acceleration behavior.
7. Finds the first qualifying peak as `Max`.
8. Uses the threshold-down crossing as `End`.
9. Filters reaches by duration, outward travel, and overlap.
10. Classifies outcomes using pellet availability, pellet loss, pellet motion,
    pellet z displacement, and hand proximity.

The outward signal is:

```text
outward = -distance(RH, pellet_home)
```

Because the signal is negative distance, a reach toward the pellet generally
moves upward toward zero. Default thresholds are therefore negative.

### Absolute

The Absolute method detects reaches from a single RH coordinate axis instead of
from RH distance to the pellet.

The method:

1. Extracts the selected absolute axis from the RH trajectory.
2. Optionally multiplies it by `-1` when **Invert coordinate** is checked.
3. Masks low-confidence RH frames.
4. Interpolates missing values.
5. Finds upward and downward threshold crossings.
6. Estimates start from pre-crossing velocity/acceleration behavior.
7. Uses the first peak in the candidate reach as `Max`.
8. Sets `End` to the first reversal after the threshold-down crossing.
9. Records additional later peaks as mini/sub-reaches.
10. Filters by duration and overlap.

If pellet context is available, Absolute detections are classified with the
same pellet-based outcome logic. If no pellet context is available, reaches are
left `Unclassified`.

## Parameters

Parameter units follow the selected input source:

- Project labels and external prediction files: **pixels**
- points3D files from SLEAP 3D projection export: **millimeters**
- Other points3D files: the file's own coordinate units

### Shared Parameters

#### KPN outward threshold

Used by both methods.

For **From pellet**, this is the lower threshold on `-distance(RH, pellet_home)`.
A candidate begins when the outward signal crosses upward through this value.

For **Absolute**, this is the absolute coordinate threshold. A candidate begins
when the selected RH axis crosses upward through this value.

#### Peak prominence

Minimum prominence required by `scipy.signal.find_peaks` when selecting reach
peaks. Larger values reject smaller/local fluctuations.

#### Min duration (frames)

Rejects reach epochs shorter than this many frames.

Default: `15`.

#### Max duration (frames)

Rejects reach epochs longer than this many frames.

Default: `100`.

#### Start padding (frames)

After the algorithm estimates the reach start, it subtracts this many frames
from the start index. This pulls the stored reach start slightly earlier.

Default: `5`.

#### Min point confidence

Minimum SLEAP point score for LH, RH, and pellet samples to be treated as valid.

Default: `0.5`.

### Filter Parameters

#### Filter LH/RH traces

Applies the first-order Butterworth low-pass filter to LH and RH coordinates
before detection. This affects:

- the RH distance trace used by **From pellet** detection;
- the selected RH axis used by **Absolute** detection;
- the LH/RH context used for pellet-based outcome classification.

The pellet trace is not filtered.

#### Cutoff frequency

Butterworth cutoff frequency in Hz.

The sampling rate is calculated from the source video frame rate. The normalized
cutoff is computed as:

```text
cutoff frequency / sampling rate
```

The cutoff must be greater than `0` and less than the sampling rate.

### From pellet Parameters

#### KPN max threshold

The higher threshold that the candidate must also reach before a peak is
accepted. The detector first crosses the outward threshold, then requires the
signal to reach this max threshold inside the candidate period.

Default: `-26.0`.

#### Min outward travel

Minimum required increase from the candidate baseline to the first peak.

For **From pellet**, this is measured on `-distance(RH, pellet_home)`. It is in
pixels for 2D inputs and millimeters for points3D inputs.

Default: `4.0`.

#### Max pellet dist. from home

Maximum pellet distance from its estimated home position for the pellet to be
considered placed/available.

The tooltip suggests:

- around `2` for 2D pixel coordinates;
- around `10-25 mm` for 3D calibration space, depending on reconstruction
  noise.

The current UI default is `15.0`.

This control is disabled for the Absolute method in the UI, although pellet
context can still be used internally for outcome classification.

### Absolute Parameters

#### Absolute axis

Coordinate axis from the RH trajectory used as the reach signal:

- `X`
- `Y`
- `Z`

For 2D inputs, `Z` is constant `0.0`, so it should generally not be used.

#### Invert coordinate

Uses the negative of the selected coordinate before thresholding. This is useful
when outward movement in your camera/calibration setup decreases the coordinate
instead of increasing it.

#### Absolute max start

Rejects candidate reaches whose padded start value is greater than this value.
This prevents detections that begin from an already-extended position.

Default: `300.0`.

## Pellet Epochs and Outcomes

The pellet logic estimates placement and loss:

- Pellet placement requires the pellet to stay near home for at least
  `0.05 s`.
- Pellet loss requires it to be absent, low-confidence, or outside the home
  distance for at least `0.1 s`.
- After loss, another pellet event is not accepted until about `5 s` has passed.

Session events can improve pellet availability. Event names containing
`delivery`, `available`, or `pellet_placed` are treated as pellet-availability
markers.

Outcomes are assigned as follows, approximately:

- `Missed`: pellet was not available at the reach maximum, or the pellet remains
  near home after the reach.
- `Grabbed`: pellet loss occurs during the reach or pellet event logic marks
  the right hand as the successful grab source.
- `Dropped`: pellet motion/z-displacement indicates a drop, or pellet event
  logic marks the pellet as dropped.
- `Unclassified`: no pellet context was available.

The `Stalled` outcome is available in the table and output format, but the
current KPN detection path does not automatically assign stalled reaches.

## Timeline and Manual Curation

Detected reaches are shown in the zoomed timeline as horizontal colored bars.
The white vertical tick inside a bar marks the reach `Max` frame.

Users can curate reaches in two ways:

- Select rows in the reach table and assign an outcome.
- Use the timeline `r` edit flow to adjust or add reach periods.

Timeline edit flow:

1. Hover over the timeline.
2. Press `r`.
3. Click an existing reach bar to edit it, or click empty timeline space to add
   a new reach.
4. Use left/right keys to adjust the current frame.
5. Left-click to lock `Start`.
6. Adjust and left-click to lock `Max`.
7. Adjust and left-click to lock `End`.

Edited reaches keep their previous outcome. Newly added reaches are
`Unclassified`. The reach table and timeline update immediately.

## Saving Results

The **Save Reaches...** button writes:

- `detected_reaches.txt`: canonical reach segments.
- `kpn_reach_details.json`: detailed per-reach metadata, when available.
- `kpn_reach_details.txt`: tabular details, when available.
- `kpn_reach_details.csv`: CSV details, when available.
- `pelletHistory.pickle`: pellet epoch history, when available.
- `reach_detection_info.json`: provenance, selected nodes, parameters, source
  metadata, and output counts.

The provenance file records the prediction source, node selections, valid frame
counts, detection parameters, session event usage, and reach counts.

## Practical Notes

- Use 2D project labels or external predictions when you want quick,
  camera-specific reach detection in pixels.
- Use points3D when you want thresholds to be physically meaningful in
  calibration units, typically millimeters.
- Recheck parameters when switching between 2D and 3D sources; pixel thresholds
  are not interchangeable with millimeter thresholds.
- For **From pellet**, verify that the skeleton has a node named `pellet`.
- For **Absolute**, verify that the chosen axis increases during outward reach,
  or enable **Invert coordinate**.
- If detections are missing, check the diagnostic counts for valid LH, RH, and
  pellet frames and lower **Min point confidence** only if the predictions are
  trustworthy enough.
